BUG-3

Level 3 called a toy bus “the bus”

Text fixed · voice pending

“Referring to the toy object simply as a ‘bus’ creates logical confusion in an educational context, as a real bus is vastly heavier than a cricket ball.”

As reported

Agreed, and it undercuts the lesson: a balance tipping toward the cricket ball reads as nonsense to a child picturing a real vehicle. The artwork is unmistakably a toy, so the copy was what was wrong. Both of the level's lines are corrected, verified by capturing what the banner actually renders rather than the source string.

Still needs a recording

Copy can be corrected in code; a voice-over cannot. The banner now says “toy bus” while the narration still says “bus”. Two clips close that gap, at the same paths:

  • Here_is_a_ball_and_a_Bus.ogg → “Here is a ball and a toy bus.”
  • Let_us_place_the_Bus_on_the_balance.ogg → “Let us place the toy bus on the balance.”

Drop the new files in and add their lengths to js/audio-lengths.js â€” typing speed is derived from clip length, so a missing entry falls back to a guess.

BUG-5

Tapping the title background triggered the voice-over

Fixed

“In the first screen the background looks tappable â€” when I tap the title, the voice-over starts.”

As reported in session

The splash backdrop is a full-screen button, and its only job was to play the title line. Two things followed on a screen whose one real control is Let’s Go: the whole picture took a pointer cursor, and pressing anywhere dimmed the entire splash. Every tap also restarted the line.

The backdrop is now inert. The title plays on arrival where the platform permits it; where the browser refuses autoplay, only Let’s Go can trigger it â€” never a stray tap on the artwork.

Autoplay is a platform setting

No browser plays audio before the user has interacted with the page, and no code gets around that. Where the game ships it will simply autoplay â€” set setMediaPlaybackRequiresUserGesture(false) on an Android WebView, allow="autoplay" on an iframe embed, or mediaTypesRequiringUserActionForPlayback = [] on iOS.

Fixed

“Add interaction sounds where they’re missing â€” tap, drag, drop and more â€” make buttons feel tappable and pressed like a real game, and show the hand cursor only on things you can actually interact with.”

As requested

Three sounds existed and all three marked a result. Every action was silent â€” including a wrong answer, which meant right and wrong were distinguishable only by reading. Six cues were added, synthesised like the existing ones so there are no new files to load. Each is detuned slightly on every fire: the same sample twice running is what makes a game sound mechanical, and children hear it before adults do.

BUG-7

Next and Try Again sat still, and hints interrupted

Fixed

“Make Try Again and Next look tappable and pressed, add a pulse animation, and give a hand hint if the child is idle for 3–5 seconds.”

As requested

When either button appears it is the only thing left to do, and both sat as still as the table. They now breathe until they are used, with the shadow travelling with the scale so the button reads as lifting off the table rather than merely growing.

The hint delay also moved off the wrong clock. It counted from the moment a phase opened, so a child four seconds into dragging an item â€” not idle â€” got a hand on screen while they were still working. It now counts from whichever came later, the hint being armed or the child’s last action.

Both halves are needed. Without the arming time, a child who has spent fifteen seconds listening to an instruction is already “idle” when the next phase opens, and the hand lands on the same frame the item becomes draggable â€” measured at 0.04 s while building this.

What this pass does not cover

Stated plainly, because a report that only lists successes is not much use:

  • I have never heard the game. Verification runs muted in headless Chrome. Sound cues are confirmed to fire, in the right order, at the right moments â€” but whether they sound right is a judgement only a person with speakers can make.
  • Synthetic taps are not trusted gestures. Where autoplay is blocked, the once-only retry logic is proven but the audio itself cannot be unlocked headlessly.
  • Level 3’s narration still says “bus” until the two clips above are re-recorded.
  • Nothing is pushed. All nine commits are local, on qa-fixes/hint-delay-and-vo-sync; main is untouched and the deployed build still serves the original code.
  • The instruction-7 word timings are tied to the current recording. If that line is re-recorded or translated, the copy falls back to flat typing rather than mistiming itself â€” but the spans would want re-measuring.
